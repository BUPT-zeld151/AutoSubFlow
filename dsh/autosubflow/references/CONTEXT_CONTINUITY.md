# 跨段连续语境与上下文交接

在阶段开始、单元边界和确需接替时使用。本契约补充 v4 的检查点字段，不改变原有文件路径和质量标准。

## 同一工作者持续执行

- 阶段 1 随真实已核验的证据建立人物/说话人、场景顺序、术语/专名和未决问题索引。不能提前将剧情猜测写成事实。
- 阶段 2 开始先读取阶段 1 完整 JA 字幕、handoff 和必要证据，建立全片概览，再逐场景/单元处理。使用 `global_context.md` 及阶段规范的语义/决策记录维护人物称谓、指代、术语译法、语气和前后呼应；具体判断保留 UID、时间及证据路径。摘要不足以确定的内容回查原始证据。
- 阶段 3 先独立完成中文盲审。盲审前只读取中文稿和必要的执行进度，不读取前阶段结论、剧情解释、术语理由或待修问题清单；恢复盲审可读取本轮自己的盲审记录。盲审完成再载入日文、语境及证据执行后续审查。即使独立重表达发生在同一上下文，也不得宣称真正盲测。
- 六分钟边界不是场景边界。对跨段问答、省略、同句重复和未完事件，保留相邻字幕/证据及尚未解开的指代，下一单元继续核实。跨段修订需记录理由、受影响 UID 和重跑检查。
- 每个单元/原子批次落盘并更新本阶段语境；一个单元通过不结束工作者。语境文件是持久备份与索引，不能把不确定结论固化为事实，也不能替代该阶段的逐句审查和最终全片一致性检查。

## 何时交接：实测门槛

正常上下文交接默认要求 **当前占用达到实际窗口的 90%**，达到后在安全检查点保存并退出，无需撑到硬上限。例如实测窗口 1,000,000、当前约 225,000 时必须继续；“下一整阶段/后面九个单元做不完”不属于上下文不足。判断对象始终是**下一原子批次**，可以减小本次工具输出或处理批量，不能减少最终审核范围。

工作者在单元/批次边界，以及准备返回 context_handoff 前执行：

```bash
python3 "<SKILL_ROOT>/scripts/context_budget.py" --dsh-home "<DSH_HOME>" --workspace "<VIDEO_WORKSPACE>"
```

DSH_HOME 由父会话提供实际运行目录或使用环境变量。脚本只读 projection cache，不读取/打印消息正文、思考或凭据，不更改运行状态。工作区内只有一个近期活跃子级时自动定位；匹配多个/没有活跃子级时不猜测，需要传确切 `--session-id`。父会话验收交接**必须**提供自己目录记录中的确切子级 id，不能拿主会话或另一子级的用量代替。

- `decision=continue`（退出码2）：同一工作者继续下一原子批次。禁止使用“感觉接近上限”“读了很多图”“已工作一小时”“已经八个单元”或节约 token 作为退出理由。
- `decision=handoff_eligible`（退出码0）：实测达到90%，保存完整交接，结果附用量输出；并非工具故障或要求重跑已完成内容。
- `decision=telemetry_unavailable`（退出码3）：缺字段/缓存过期/身份不明确等，**不是耗尽凭据**。继续小批执行、持续保存进度，先修正用量定位；不能把未知写成 observed:true。其他客户端可使用等价且可信的当前用量工具，仍须满足身份与90%门槛。

实际占用优先取 DSH `pressureTokens` 和可用 `projectedTokens` 的较高值；后者可能含采样后的表面增量。不是累计输入/输出/缓存计费总量，也不是简单的字符估算。界面窗口容量来自当前路由记录，不能想当然使用 1M。缓存超过5分钟不作为当前交接凭据。

**唯一的容量例外**：供应商/运行时已经明确返回本请求超出输入上下文长度的错误，可在低于界面90%时保留错误原文、来源和请求记录路径，由父会话验证；可能是界面容量配置不符，不能假装已消耗1M。不能把 max output tokens、网络、命令超时、内存故障或工作量描述当成该例外。外部中断恢复与用户暂停分别记录，不伪装为上下文交接。

只读脚本和 Markdown 不是运行时强制拦截器：如果 one-shot 子级违反契约先返回，原实例已经结束，主会话不能靠事后拒绝让它回到原上下文；须记录异常并恢复，不能将不足25%的交接解释为正确行为。

## 交接内容与可靠性

继续使用本阶段 `progress.json`、`state/context_handoff.json`、`global_context.md`（适用于该阶段/轮次时）、证据索引及 v4 要求的 `CONTINUE_IN_NEW_CHAT.md`。保留 v4 已有字段：

`phase,prompt_version,source_paths_and_hashes,completed_units,current_unit,current_step,last_verified_window_or_uid,next_exact_action,pending_tasks,open_issues,work_paths,quality_gate_results,asr_backend,memory_status`。

上下文交接在此基础上补充：

- `handoff_reason`：真实原因；上下文不足为 `context_pressure`，工具中断恢复另注明。
- `context_pressure`：context_budget.py 的真实 session_id、当前用量、窗口、比例、sample_seq、cache 更新时间、decision 与 handoff_allowed；不能只填工作量/估计，更不能伪造 observed:true。供应商超限例外附 error_evidence_path，由父会话核验。
- `continuity`：本阶段已建立的语境/场景/术语/翻译决策的路径和必要摘要、关键 UID；阶段 3 注明当前审查轮次及盲审已完成范围，禁止交接未允许读取的前序判断。
- `open_scene`：跨段未完场景、问答、说话人/指代、前一关键 UID、下一步核查；没有未完场景则明确为空。
- `checkpoint`：最后可信完成位置、当前部分完成文件、尚未审核的范围和恢复动作。部分产物不得标为已验收。

以上字段可嵌套在现有 JSON 中，不要求迁移旧项目。旧交接缺字段时，从现存进度/证据建立必要恢复信息，不能编造缺失语境。原子写入、重新读取核对，返回真实路径；不要只把交接放在聊天最终回复里。

## 接替者/下一阶段启动

先读取自己的阶段 Prompt 和合法范围内的交接/索引，再核对原片身份、检查点和实际文件。重建人物/场景、已确认与未知事实、译法约定、未完问答及必要的相邻字幕；摘要不足则查具体 UID 和原始证据。阶段 3 的中文盲审限制优先。

复用可信完成部分；修复影响边界的具体问题，不因换人重做全片。恢复后的范围仍是当前阶段全部剩余工作。跨阶段始终使用完整阶段成果、语境索引及可回查证据，不能假设不同子智能体共享聊天记忆。
