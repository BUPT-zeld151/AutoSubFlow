# PROMPT 03 v4｜全片中文盲审、语义具体化复核与证据驱动自主修复

> **独立新会话，纠错而非重做整个影片。** 输入：原视频、已生成的日中 SRT、Prompt 01/02 的证据索引与问题记录（如可用）。输出经实际修订的双语终稿、修改记录与未决证据边界。**全文字幕都要审，但不能为了审稿再次阅读全片 1 FPS 图像；视频只在具体的语义/声学风险被触发时定向深入检查。**

## S. 三阶段通用不可降级运行协议

1. **不改变质量目标，只改变证据投入位置。** 全部中文字幕与日中对应关系、每个连续对话场景的连贯性、每个已触发纠错任务都必须核验。v4 **不要求**全片基础帧全部输入大模型；禁止以旧 v3 的“每秒 1 帧全片必看”为验收条件。也不得擅自把已触发的局部 1 FPS/加密观察再缩成一张关键帧。
2. **上下文不足不能快扫收尾。** 将任务划为 5–8 分钟处理单元及更小原子批次；每批完成后落盘。若估计无法高质量完成下一完整批次，保存 `progress.json`、`state/context_handoff.json` 和 `CONTINUE_IN_NEW_CHAT.md`，在当前会话停止后请求用户开启**新会话**继续。不得声称自行创建了新会话，不得将未审内容标为已完成。减少单批大小可以，减少总审核范围不可以。
3. **16GB Apple Silicon 统一内存保护。** 开工核实 `sysctl -n hw.memsize`；在重型任务前后及每单元边界观察 `memory_pressure`、`vm_stat`、`sysctl vm.swapusage` 和主要进程 RSS。**同一时刻最多一个重型任务**：Whisper/Metal、VAD 大模型、批量视频解码/镜头检测/图片处理不得重叠；大规模预处理流式、串行，工具线程审慎设限；不预加载两小时图像到内存。出现明显压力或 Swap 持续升高，停止启动新任务，等待/安全结束自己发起的任务，释放缓存并保存检查点；不得杀用户进程。日志入 `state/resource_log.jsonl`。内存紧张不等于上下文紧张；切换会话不能增加物理内存。
4. **证据诚信。** `produced`（文件已生成）、`opened`（实际被视觉模型查看）、`reviewed`（有具体审核结果）、`verified`（证据充分）、`uncertain`（查过但无法判断）、`unreviewed`（未做）、`blocked`（无法执行）彼此不同。VAD/波形有活动≠可辨语音；Whisper 结果≠真值；有关键帧≠已理解动作；上下文“合理”≠声音确实说过。
5. **保留原始材料和稳定标识。** 所有时间戳使用全片绝对毫秒；原音视频和初次 Whisper 输出不可覆盖；修改、分合字幕保留 `source_uid → output_uid` 追踪。脚本用于切片、索引、门禁及声学统计，不能代替真实的视听语义判断。不要擅自用子代理或第三种大型识别模型代替指定主模型决策。
6. **最小可恢复交接。** `context_handoff.json` 至少含 `phase,prompt_version,source_paths_and_hashes,completed_units,current_unit,current_step,last_verified_window_or_uid,next_exact_action,pending_tasks,open_issues,work_paths,quality_gate_results,asr_backend,memory_status`。原子写入并重新读取校验。跨会话恢复时先读本 Prompt、交接文件和证据索引，再从最后可信检查点继续；不能因新会话缺少旧聊天上下文就重做已经验收的全部工作或忽略未完成项。

## 0. 根本目标与证据边界

本阶段把中文 SRT 当成需要严格质检的**外部初稿**，不是已正确的成品。最大限度自主解决：①明显病句和翻译腔；②词义笼统、似是而非，观众无法理解具体行为/对话目的；③条件/否定/说话人与上下文逻辑错；④机械重复、时间轴坍缩、漏句或 ASR 幻觉；⑤表面合理但对话场景内容被误解。

**不得把“发现了问题，建议人工复核”当成任务完成。** 应当基于可用证据实际修复，只有相关证据确实不足时允许 `evidence_limited`。不得为了消灭待审项而根据剧情编造原声、反转否定或改变说话次数。**中文自然 ≠ 忠实；画面合理 ≠ 日语真实说过。**

## 1. 输入保全与独立初审

1. 用 `ffprobe` 与源文件元数据确认视频、ja/zh SRT 属于同一素材；审查编号连续性、显示时长、重叠、同步、末尾覆盖。将两份输入 SRT 只读归档到 `.subtitle-final-review/input/`，保存 SHA-256；所有修改输出独立文件，不覆盖原稿。保留稳定 `source_uid`，修改时维护旧→新映射。
2. **先进行中文盲审**，不要先阅读前阶段的“核验通过”结论、人工待审清单或修改理由。按照连续 15–30 条为批次、前后 3–5 条为局部上下文，**100% 阅读并检查全片每句中文**：语病、连贯性、条件结果、问答、人物指代、无意义重复、过度模糊、字幕时长/阅读速度是否离谱。
3. 对每句增加**“场景具体性检查”**：观众能否仅凭这一组连贯对白明白谁向谁提出何种要求、为什么同意/拒绝/威胁、谈论什么对象？如果当前译文大量写“那个/这样/这事/你知道的”，而原文或可得的语境有明确指向，须标为 `semantic_vagueness`，**不许因为语法无错就放行**。
4. 对全部日中条目作**第二轮全量语义对照**，独立核查日文条件/否定/比较/人称、真实所指、职业/人名/企业名、言语行为、问答关系及是否添加/遗漏信息。不能因原日文已有 `verified` 就不再检查其明显病句或词义疑点；若无法由原稿判断真实词音，进入原声事实核查级别。
5. 保存 `chinese_blind_audit.jsonl` 与 `bilingual_audit.jsonl`；每条稳定 UID 都有审查记录，疑点分别含 `issue_id,severity,category,example_span,question_to_resolve,route,status`。机器异常阈值只负责提醒，**不是删改的唯一证据**。

## 2. 主动发现“每个单句似乎合理，但整段对白根本不知所云”

这一项是 v4 的新核心，不是可选抽样。先对每个连续对话场景在不展示旧审校判断的情况下，生成简短 `dialogue_coherence_audit`：

- 场景中有哪些已知/未知说话人、彼此关系、每人的实际发言立场（只根据已见证据）；
- 当前谈论的具体事件/物品/机会/请求或限制是什么；
- 哪一句提出主张/暗示、哪一句回答/拒绝、为什么这个回答与前文相关；
- 哪些原有中文虽然语法通顺，却让整段对话的**动作目标、潜在交易、抗议内容或反应对象**含糊不明；
- 哪些信息是日文直接表达的、哪些只是有根据的言外之意、哪些无充分证据；
- `coherence_status=clear / review_required / evidence_limited`；不是 `clear` 必须进入纠错队列。

**不要把影片特定情节当成固定模板。** 对师生/就业推荐之类的对话，应根据当前素材实际核对人物关系、提议、暗示、拒绝和投诉对象；字幕如果“句句能读，但不知道为什么拒绝”，就是实际质量缺陷。应重新从日文文字及视频核查，而不是只换同义词。

## 3. 分级纠错：从低成本到足够充分的证据，而非机械重跑 ASR

所有问题先分 `P0(颠倒意思/严重时间错误)、P1(语义模糊/逻辑错/病句)、P2(风格/冗余)`，然后另分 `L1/L2/L3` 路径；**优先级和证据类型不是一回事**。

### L1：纯中文问题直接改

语法搭配、错别字、冗词、自然口语、不改事实的断句/标点，直接在连续中文上下文中重写；保存具体病灶、旧/新译文和前后对白回归结果。若改写必须知道真实指代、否定或发声时间，不能假装 L1 足够，升级 L2/L3。

### L2：语义具体化与定向视觉复查（语义问题默认）

针对人物/动作/对话目的/威胁/拒绝对象/含蓄暗示/具体动作与位置等风险，先查现有日文上下文及 `meaning_record`/场景卡的**证据**，旧结论不可信时重新看原片。

- 以完整相关事件/问答为核查范围，通常取前后各 10–20 秒，必要时拓展到整段对话或前后镜头；把彼此相关的字幕合并成一个审查单元，避免同一场景反复消耗大量上下文。
- **仅对该触发区间**至少按 1 FPS 连续读取真实画面；人物位置/对象接触/具体动作/面部情绪变化/镜头切换造成歧义时再按 0.2–0.5 秒加密、观察原始高清局部，必要时短视频。**没有触发的其他影片时间段不需要重新读全片 1 FPS。**
- 输出具体证据链：谁在场、相互身份关系和空间位置、谁对谁做了何种可观察动作、对象/接触位置/起止顺序、谁有可见反应以及反应如何；情绪、意图和潜台词是推断，不是可见事实。对具体对象、动作位置与状态变化，应依据可观察证据准确记录；若要断言某项动作已经发生或完成，需要连续时间证据，单帧重叠或静态遮挡不足为证。确实看不清时明确“不明”，不要用“在互动”“正在发生某事”糊弄。必须写 `frame_ids_opened`，抽出却未打开的图不得冒充已观察。
- **明确检验两种不同的错误**：①明说的具体内容被译成模糊口语；②只是语境暗示的内容被译成未经证实的直白断言。修正时保持与原文相同的信息明确程度，同时让中文观众能理解这句如何回应上一句。
- 可从已经存在的合法日语多义解读中结合场景选择更可信的一种。**如果修复必须判断日文音频中究竟有无 `ない` 等词、哪个具体名词、究竟喊过几次，则视觉不能裁决**，转 L3，不得凭画面改日文。
- 输出 `visual_evidence.jsonl`：`issue_id,scene_id,video_window,base_frame_times,frame_ids_opened,detail_frame_ids_opened,visible_facts,inferred_intent,japanese_compatible_readings,chosen_zh,reason,remaining_limitations`。修复后检查相邻 3–5 句及整个相关事件，避免只改单句造成新的逻辑不通。

### L3：真正依赖原声词音/次数/边界的疑点

仅当 L1/L2/原有识别记录不足以确认事实时执行：

1. 先检查第一阶段完整音频窗口审计、原始 Whisper 输出、VAD、波形/谱图、原始音轨与上下文；这些线索可能定位疑点但**不能通过波形直接证明“说了哪句话”**。
2. 环境确实支持音频听辨时，优先核查完整局部上下文；不支持则明记 `audio_direct_listening=false`，不得声称亲耳回听。
3. 只有对该具体疑问预期有收益时，才使用已验证的本机 `whisper.cpp + large-v3 + Metal` 对包含上下文的短音频做**一次有针对性的**重新切片/调整参数识别，保留两个输出及推断；不得机械反复重跑长视频或引入未经授权的新大型模型。
4. 证据充分时同步更正日文与中文及时间轴、原 UID 映射；如声音仍无法确定，采用真实可证的保守表达或明确 `evidence_limited`。不能把故事合理性当作原声音素证据。

## 4. 字幕时间轴与重复专项

对 SRT 全量计算并审查：`duration <= 0.5s` 却含较长中文（例如 ≥8 字）、`duration <= 1s` 内容过长、汉字粗略阅读速度 >12 字/秒（风险）或 >20 字/秒（严重）、连续重复、机械寒暄幻觉、重叠/越界及整句挤成 0.2–0.4 秒。**阈值只生成待核查项，不自动证明是错。**

先区分中文冗余、真实反复发声、源字幕时间戳坍缩、合并错误和 Whisper 幻觉；涉及真实语音次数/边界时走 L3。不得为了降低字数随便删真实的短促应答。对确定的时间错误使用完整局部问答重建双语相同时间轴，并执行新的 SRT 合法性和邻句检查。

## 5. 自主裁决、实际修复与“终稿再生成”

问题按照 `open → resolved / rejected_with_evidence / evidence_limited` 闭环：

- `resolved`：必须有修改前后、依据 L1/L2/L3 的证据、实际修订后的字幕及邻近条目回归结论。
- `rejected_with_evidence`：证明原句其实正确，列出原先疑点为什么不成立。
- `evidence_limited`：用过所有与该疑义有关且可用的合理方法仍不能证实；记载具体缺失证据、不能确定什么，不能以泛泛“待人工复核”偷懒。

完成修复后，对**所有仍然可能含混或不够自然的句子**执行“从日文语义重新表达而不是给旧文找错”；用 `literal_proposition`、`referent_map`、`speech_act`、`scene_context` 生成新中文，与旧稿比对后选择更忠实且自然的表达。若新译法在原先上下文中已看到旧文，不准虚称真正盲测。

必须针对每个 `semantic_vagueness` 记录：`what_was_vague,actual_referent_if_supported,how_context_resolves_it,old_zh,new_zh,semantic_fidelity_check`。不能仅将“那个”换成“这个”就判已解决。也不要为了多改句子而破坏准确的译文。

## 6. 终稿回归检查与验收

**回归 A：全片中文再次裸读。** 只看最终中文 SRT，逐句并作为连续场景读，重新查中文语病、指代、语义明朗度、人物动机与答复关系、无意义重复及阅读速度。检查不能仅覆盖曾被发现的问题；全部字幕 UID 必须有回归状态。

**回归 B：已修改条目的日中对照。** 逐条核对否定/条件/时态/人物指代/具体词义/含蓄程度，和相邻未改条目是否矛盾。已证实音频问题检查双语切分/时间戳一致性。

**回归 C：对话场景连贯性复核。** 所有连续对话场景均需 `scene_coherence_status`，存在“句句读得通，但整段目的/指代不明”的 `review_required` 场景不能算已通过。证据确实不足要单列 `evidence_limited`，不可为过关编造意思。

**机读门禁**：输入条目全量中文盲审、日中对照与最终中文回归覆盖 100%；对话场景连贯性审查全覆盖；所有触发问题都有处理结论；所有实际触发视觉区间有被打开的相关帧和事件分析，**不要求全片 1 FPS 查看或所有字幕都带图像**；所有 SRT 时间戳合法、日中同轴、UID 对应完整、输入文件未覆盖。不得用“结构 PASS”冒充语言/事实绝对无误。旧版按全片 1 FPS 和每句视频帧检查的 `qa_gate.py` 与 v4 不兼容，必须更新门禁后才能使用。

### 6.1 已知失败案例的回归测试（仅当本次影片确实包含这些条目）

- 例如约 **0.48 秒**内塞入“什么？什么？什么？什么？怎么了？”的字幕：先查阅读速度与翻译重复，再分辨真正的发声次数/时间戳问题；不能为了可读性未经音频证明随意删真实发声。
- 例如“你要是听话，就受到惩罚”一类**条件与后果看似颠倒**的字幕：先核对前后威胁关系、原日文条件句和画面事件；若最终依赖否定词是否真实存在，进入 L3，不能直接按常识增补“不”。
- 例如就业推荐对话**句句字面通顺却没有表达清楚关系、提议、暗示与拒绝对象**：标为场景级 `semantic_vagueness`，不能只做单句口语润色。

上述例子只作为检测机制的测试用例，不预设正确译法，不要求其他影片强行匹配这些情节，也不能只改这些条目而忽略全片。

## 8. 开始执行

依次进行：输入保全 → 全片中文盲审 → 全片日中语义对照及场景连贯性审核 → L1/L2/L3 定向自主纠错 → 新中文编辑 → 全片回归和交付。可以以小批次存档，但不能提前把仍未审的后半部当成最终字幕。对已明确存在的病句/逻辑问题必须实修，不得只交“人工复核建议”。
